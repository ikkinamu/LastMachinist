LAST MACHINIST — POST-MVP CODEX PATCH 002
PATCH_002_HANDWHEEL_15DEG_1MM_FIXED_POINTER_CODEX

[ROLE]
이 파일은 설명용 기획서가 아니라 Codex가 현재 Last Machinist Unity 프로젝트에
직접 적용해야 하는 실행 작업지시서다.

이 PATCH를 읽은 뒤 먼저 현재 구현을 조사(AUDIT)하고,
기존 정상 동작을 최대한 유지하면서 아래 변경사항을 실제 프로젝트에 구현하라.

전체 시스템을 임의로 재작성하지 말고 필요한 범위만 수정하라.

Last_Machinist_MVP_Development_Spec_v0.10_REVIEWED.txt

============================================================
1. 이번 PATCH의 목표
============================================================

선반 X/Z 핸드휠의 조작 규칙을 다음과 같이 변경한다.

×1 기준:

15° 회전 = 1 mm 이송

따라서:

15°  = 1 mm
30°  = 2 mm
45°  = 3 mm
90°  = 6 mm
180° = 12 mm
360° = 24 mm

화면상의 핸드휠도 실제 이송량과 동일한 회전량을 표시해야 한다.

또한 핸드휠 UI는 반드시:

1. 회전하는 Wheel_Disc
2. 회전하지 않는 Fixed_Pointer

두 요소로 분리한다.

Wheel_Disc만 회전한다.
Fixed_Pointer는 화면에 고정한다.

============================================================
2. 변경 대상
============================================================

현재 프로젝트를 조사하여 실제 클래스/Prefab/UI 구조를 확인한 뒤
아래 기능과 직접 관련된 파일만 수정한다.

- Lathe Handwheel Input
- X/Z Axis Input
- Mouse Wheel Input
- UI Handwheel Drag Input
- Handwheel Command / Axis Move Command
- 이동 배율 시스템
- Handwheel UI
- Handwheel Sprite/Image
- Handwheel rotation feedback
- Fixed pointer UI

Quest, Dialogue, Inventory, Measurement, Save, Exploration,
Turning Geometry 등 이번 작업과 무관한 시스템은 수정하지 않는다.

단, 현재 구조상 필수적인 최소 연결 수정은 허용한다.

============================================================
4. Handwheel 핵심 변환 규칙
============================================================

Handwheel 회전각과 축 이동량의 기준을 중앙화한다.

기본 상수 개념:

DEGREES_PER_STEP = 15°
MM_PER_STEP = 1 mm

×1 기준:

movementMm = rotationDegrees / 15° × 1 mm

가능하면 변환 규칙을 여러 스크립트에 중복 하드코딩하지 말고
하나의 명확한 계산 계층에서 관리한다.

============================================================
5. 이동 배율
============================================================

기존 ×1 / ×10 / ×100 구조는 유지한다.

적용 결과:

×1
15° = 1 mm

×10
15° = 10 mm

×100
15° = 100 mm

계산 개념:

movement =
(rotationDegrees / 15°)
× 1 mm
× currentScale

배율이 마우스 휠 경로와 UI 핸드휠 경로에서 다르게 적용되면 안 된다.

============================================================
6. 입력 경로 통합
============================================================

다음 입력은 같은 Handwheel 이동 규칙을 사용해야 한다.

- 마우스 휠
- 화면 핸드휠 직접 드래그
- 기존에 존재한다면 터치 기반 핸드휠 조작

입력 장치별로 공작물/Tool 좌표를 직접 수정하지 않는다.

반드시:

INPUT
→ Handwheel rotation delta
→ Handwheel movement conversion
→ Scale
→ 기존 Axis Movement Command
→ Visual update

순서를 따른다.

============================================================
7. 마우스 휠 처리
============================================================

마우스 휠은 물리적인 각도 입력 장치가 아니므로
현재 프로젝트의 wheel delta를 Handwheel 회전각으로 변환한다.

변환 기준은 한 곳에서 관리한다.

마우스 휠 입력으로 실제 축이 움직이면
화면 Wheel_Disc도 그 이동량에 해당하는 각도만큼 반드시 회전해야 한다.

예:

×1 상태에서 실제 축이 1 mm 이동
→ Wheel_Disc 15° 회전

×1 상태에서 실제 축이 4 mm 이동
→ Wheel_Disc 60° 회전

화면 회전과 실제 이송량이 서로 독립적으로 움직이면 안 된다.

============================================================
8. Handwheel 이미지 규칙
============================================================

Wheel_Disc는 다음 구조를 가져야 한다.

- 한 바퀴 = 360°
- 24등분
- 눈금 간격 = 15°
- 총 24개 눈금 위치
- 90° 간격 주요 눈금은 조금 더 강조 가능

현재 준비된 휠 아트처럼
0 / 6 / 12 / 18 표기를 사용할 수 있다.

의미:

0 = 0°
6 = 90°
12 = 180°
18 = 270°

한 바퀴 24 step을 시각적으로 읽을 수 있어야 한다.

============================================================
9. Wheel_Disc / Fixed_Pointer 분리 — 중요
============================================================

핸드휠 UI를 별도 오브젝트로 분리한다.

권장 Hierarchy 예:

HandwheelRoot
├── Wheel_Disc
└── Fixed_Pointer

또는 현재 UI 구조에 맞는 동등한 분리 구조를 사용한다.

[Wheel_Disc]

- 핸드휠 본체
- 24등분 눈금 포함
- 0 / 6 / 12 / 18 숫자 포함 가능
- 실제 Handwheel rotation 값에 따라 회전

[Fixed_Pointer]

- 현재 눈금 위치를 읽는 기준선
- 얇은 검은 선 형태
- 장식적인 빨간 화살표 사용 금지
- Wheel_Disc와 별도 Sprite/UI Image
- 화면에 고정
- 절대 Wheel_Disc와 함께 회전하지 않음

============================================================
10. 절대 금지 — 포인터 동반 회전
============================================================

다음 구현은 FAIL이다.

Wheel_Disc 이미지 내부에 포인터까지 그려 넣고
이미지 전체를 회전시키는 방식.

이렇게 하면 포인터가 휠과 같이 회전하므로 사용하지 않는다.

Fixed_Pointer는 반드시 Wheel_Disc와 독립적인 UI 요소여야 한다.

Unity Hierarchy에서도
Wheel_Disc의 회전 Transform 영향을 Fixed_Pointer가 받지 않도록 한다.

예:

잘못된 구조:

RotatingWheel
├── WheelImage
└── Pointer

RotatingWheel 자체를 회전
→ Pointer도 같이 회전
→ FAIL

허용 구조:

HandwheelRoot (고정)
├── Wheel_Disc (회전)
└── Fixed_Pointer (고정)

============================================================
11. Pivot / Rotation
============================================================

Wheel_Disc의 Pivot은 휠 중심에 정확히 위치시킨다.

회전 시:

- 중심이 흔들리지 않아야 한다.
- 이미지가 타원형으로 왜곡되지 않아야 한다.
- 회전 중 위치가 이동하지 않아야 한다.
- 포인터 위치는 변하지 않아야 한다.

UI RectTransform을 사용한다면
Wheel_Disc의 중심 Pivot 기준으로 회전한다.

============================================================
12. 화면 핸드휠 직접 조작
============================================================

플레이어가 화면 Wheel_Disc를 마우스로 직접 드래그하여 조작할 수 있는
기존 기능이 있다면 유지한다.

드래그 각도 변화량을 계산하여 동일한 Handwheel 변환 규칙을 사용한다.

예:

플레이어가 Wheel_Disc를 45° 돌림
×1
→ 3 mm 이동

그리고 Wheel_Disc도 실제로 45° 회전된 상태를 표시한다.

Fixed_Pointer는 그대로 고정되어 있어야 한다.

============================================================
13. 이미지/에셋 적용
============================================================

이번 PATCH에서 사용하는 UI 에셋은 개념적으로 최소 두 개다.

1. Wheel_Disc 이미지
2. Fixed_Pointer 이미지

Fixed_Pointer는 매우 단순한 검은 기준선이어도 된다.

현재 프로젝트에 기존 Handwheel 이미지가 있고
포인터가 이미지에 합쳐져 있다면:

- 기존 단일 이미지를 그대로 회전시키지 않는다.
- Wheel_Disc용 이미지와 Fixed_Pointer를 분리해서 사용한다.

복잡한 휠을 Unity Primitive 조합으로 억지로 재현하지 않는다.

외부 Sprite를 사용하는 구조를 유지한다.

============================================================
PATCH_002 REVISION 2 — POINTER POSITION / WHEEL LEGIBILITY
============================================================

[목적]
현재 구현에서 확인된 두 문제를 수정한다.
1. Fixed_Pointer 위치가 의도와 다르다.
2. Handwheel이 너무 작아 숫자와 15° 눈금을 읽기 어렵다.

새 PATCH 번호를 만들지 말고 PATCH_002의 수정 작업으로 처리하라.

[Fixed_Pointer 정확한 위치]
Fixed_Pointer는 회전 바늘이 아니다.
Wheel_Disc의 바깥쪽 정확한 12시 방향에 놓이는 고정 인덱스 마크다.

- 짧고 얇은 검은 기준선으로 표현한다.
- 포인터 끝은 Wheel_Disc 외곽 눈금 링의 12시 위치를 가리킨다.
- 휠 중앙까지 내려오면 안 된다.
- 휠 내부를 가로지르면 안 된다.
- 숫자와 눈금을 가리면 안 된다.
- Wheel_Disc가 아무리 회전해도 포인터의 위치와 각도는 변하지 않는다.

권장 Hierarchy:
HandwheelRoot [고정]
├── Wheel_Disc [회전]
└── Fixed_Pointer [고정]

HandwheelRoot 전체를 회전시키지 말고 Wheel_Disc의 RectTransform만 회전시켜라.

[Handwheel 크기 확대]
현재 X/Z Handwheel의 실제 UI 표시 크기를 확대하라.
원본 이미지 해상도만 키우는 것으로 끝내지 않는다.

1920×1080 Reference Resolution에서 별도 확대 없이 다음이 즉시 읽혀야 한다.
- 0
- 6
- 12
- 18
- 24개의 15° 눈금
- Fixed_Pointer가 현재 가리키는 눈금

특정 픽셀 크기를 무조건 하드코딩하지 말고 현재 Lathe HUD를 먼저 확인한 뒤,
숫자와 눈금의 판독성을 확보하면서 다른 핵심 UI를 과도하게 가리지 않는 크기로 설정하라.

X축과 Z축 휠 모두 같은 가독성 기준을 적용한다.

[직접 조작 영역]
Wheel_Disc를 확대했다면 Pointer/Drag/Raycast 영역도 새 크기에 맞춰 조정하라.
보이는 휠은 큰데 작은 기존 RectTransform에서만 드래그가 인식되는 상태는 FAIL이다.

[해상도 대응]
