5.  TARGET 첫 Quest는 직사각 Plate + Through Hole 2개. 두 Hole은 같은
    Diameter, 서로 다른 X/Y Position. Preset Target을 사용한다. 치수는
    현재 Test Stock/Tool에 맞춰 유효한 값으로 정한다. Hole은 Plate
    밖/Clamp 영역 밖에 있어야 하며 과도한 공차를 요구하지 않는다.

6.  BENCH DRILL ROLE Lathe Tailstock Drill:

-   회전체 중심축 Hole
-   Lathe Z 방향

Bench Drill: - 고정 Workpiece - Drill Bit 회전 - X/Y 위치 선택 - Quill Z
Feed

Hole Geometry/Data는 가능한 범위에서 공통 구조를 쓰되 Machine Control은
분리한다.

7.  COMPATIBILITY 최소:

-   Plate Compatible
-   SquareBar Compatible
-   RectangularBar Compatible

RoundBar/Tube는 안전한 V-block/Fixture가 없으면 Incompatible로 유지
가능. Incompatible 선택 시 이유 표시, Item 삭제 금지, Available 유지.

8.  WORKPIECE INSTANCE Workshop [탁상드릴] → 실제 Inventory Instance
    선택 → Bench Drill. 무료 가짜 Test Plate 자동 생성 금지. Quest 지급
    소재도 실제 WorkpieceInstance여야 한다.

Available → InMachining. 취소/초기화 실패 → Available. 가공 완료 → 같은
Instance의 CurrentGeometry/HoleFeatures 갱신. InstanceId 유지.

9.  VIEW 최소 표시: Drill Bit / Chuck / Quill / Workpiece / Table /
    Fixture / Hole Position / Spindle.

권장 Camera: - Perspective/Isometric - Top View

Top View는 X/Y Hole Position 확인용.

10. FIXTURE 손으로 공작물을 들고 정상 가공하는 표현 금지. 최소
    Vise/Clamp + Fixed State.

Load → Clamp → Machining Enabled. 고정 전 Cutting Feed는 차단하거나
명확한 Safety Warning. 공작물 고정은 실제 Gameplay State다.

11. X/Y LOCAL COORDINATE Hole 위치는 Workpiece Local Coordinate 기준.
    권장 기준면/모서리에서 X/Y.

HoleFeature: - FeatureId - CenterX - CenterY - Diameter - Depth -
IsThrough - ToolId - OperationHistory

World Position을 Source of Truth로 사용하지 않는다.

12. POSITION CONTROL CNC 좌표 자동입력보다 수동 장비 느낌 우선. 권장:

-   X Handwheel
-   Y Handwheel

현재 상대 X/Y Reading 표시. 기존 Handwheel 코드를 재사용 가능하나 Lathe
X/Z State와 섞지 않는다.

13. ZERO SET X/Y Reference Zero 지원 가능. Zero Set은 Actual
    Position/Hole Geometry를 바꾸지 않고 Display/Reference Offset만
    변경. Actual Position != Display Zero Offset != Relative Reading.
    PATCH002 철학 유지.

14. DRILL BIT Preset Diameter 여러 개 지원. 예: Ø4/Ø6/Ø8/Ø10. 기존 Tool
    Data와 통합. 잘못된 Drill Bit를 골랐으면 실제 Hole도 그 Diameter가
    되어야 한다. Target Diameter로 자동 보정 금지.

15. SPINDLE/CUTTING CONDITIONS 최소 Cutting 조건:

-   Workpiece Loaded
-   Workpiece Fixed
-   Drill Bit Mounted
-   Spindle ON
-   Bit/Surface Contact
-   Quill Cutting Feed

조건 미충족 시 Hole Geometry 생성 금지.

16. QUILL Bench Drill 독립 Quill Z. 권장 Dedicated Quill Feed/Handwheel.
    Approach → Contact → Cutting → Required Depth → Retract. Through
    Hole은 Workpiece Thickness 기준 판정.

17. HOLE GEOMETRY Hole은 Visual Decal만이 아니라 실제 WorkpieceInstance
    Feature다. 가공 후 Inventory/Measurement/Evaluation/SaveLoad가 같은
    HoleFeature를 사용한다.

18. VISUAL HOLE Top View에서 실제 위치/크기 확인 가능. Workpiece 이동과
    함께 Hole 유지. 가능하면 Mesh/Geometry 기반. 단순화하더라도 Visual과
    Hole Data의 Position/Diameter 불일치 금지.

19. MULTIPLE HOLES 한 Workpiece에 여러 HoleFeature 저장. Quest03 Hole
    A/B 각각 독립 FeatureId/Position/Diameter/Depth. 두 번째 Hole이 첫
    번째를 덮어쓰면 FAIL.

20. MEASUREMENT 기존: TrueDimension / InstrumentReading /
    RecordedMeasurement 분리 유지.

최소 검사 대상: - Hole Diameter - Hole Position X - Hole Position Y -
필요 시 Plate 기본 치수

Target/True 값을 자동 공개하지 않는다. 위치 측정 장비가 아직 부족하면
최소 검사 방식을 명시하고 향후 Height Gauge/Surface Plate 확장 가능하게
한다.

21. EVALUATION 최소:

-   Hole Count
-   Hole Diameter
-   X Position
-   Y Position
-   Through/Depth
-   Shape Compatibility

실제 Workpiece Geometry를 Target Feature와 비교한다. “드릴 버튼을
눌렀는가”만 검사하면 FAIL.

22. WRONG HOLE / RETRY 잘못 뚫은 Hole은 자동 삭제되지 않는다. Target
    2개인데 실제 3개면 Extra Hole 감지. 영구 Quest Failure는 피하고 새
    Workpiece로 재시도 가능.

Retry 버튼으로 기존 Workpiece를 원상복구하지 않는다. 잘못 가공한
Instance는 그대로 남고 새 소재를 실제 Inventory에서 사용한다.

23. INVENTORY AFTER MACHINING 가공품을 새 가짜 Item으로 교체하지 않는다.

Before: Plate, InstanceId=A, HoleFeatures=[]

After: Plate, InstanceId=A, HoleFeatures=[HoleA,HoleB]

같은 InstanceId 유지.

24. DELIVERY 실제 가공된 WorkpieceInstance를 납품 대상으로 선택. 납품 시
    Evaluation.

PASS → Quest Complete + 기존 Ownership 규칙에 따라 납품 처리. FAIL →
결과 표시 + Workpiece 상태 유지 + 다른 소재로 재도전.

============================================================ 4. REQUIRED
FAILURE-PATH TEST
============================================================

정상 성공 경로만 테스트하면 안 된다.

최소 다음 실패 경로를 실제로 검증한다.

CASE A — Fixture 없음 EXPECTED: Cutting 불가.

CASE B — Spindle OFF EXPECTED: Hole 생성 없음.

CASE C — Wrong Drill Diameter EXPECTED: 선택한 실제 Diameter로 Hole
생성. Evaluation에서 오차 검출.

CASE D — Wrong X/Y Position EXPECTED: 실제 잘못된 위치에 Hole 생성.
Evaluation에서 오차 검출.

CASE E — Extra Hole EXPECTED: 세 번째 Hole이 실제 Workpiece에 남음.
Evaluation에서 Extra Hole 검출.

CASE F — Retry EXPECTED: 기존 잘못 가공한 Workpiece가 원상복구되지 않음.
새 WorkpieceInstance로 재시도 가능.

CASE G — Incompatible Shape EXPECTED: Machine Load 차단. Item 손실 없음.

CASE H — Save/Load EXPECTED: HoleFeature A/B와 실제 위치/직경/깊이 유지.

PASS FAIL BLOCKED NOT APPLICABLE

BLOCKED를 사용할 경우 반드시: - 무엇이 막았는지 - 코드 문제인지 환경
문제인지 - 재현 방법 - 다음 조치 를 기록한다.

자동화하지 않았다는 이유만으로 테스트 자체를 생략하지 않는다. 자동화가
어렵다면 Manual Test로 수행한다.

============================================================ 8. FAILURE
FIX LOOP ============================================================

테스트 실패 시:

FAIL → 원인 분석 → 수정 → 해당 테스트 재실행 → 관련 Regression 재실행

수정 후 이전 PASS를 그대로 가정하지 않는다.

특히 다음 영역 수정 시 관련 Regression을 다시 수행한다.

SaveData 변경 → Save/Continue + 기존 Save Regression

Workpiece Geometry 변경 → Inventory + Lathe + Exploration Recovery
Regression

Input 변경 → Lathe + Exploration + Bench Drill Input Regression

Quest 변경 → Quest01 + Quest02 + Quest03 Regression

Dialogue 변경 → Prologue + Quest Dialogue Regression

============================================================ 9. TEST
ARTIFACTS ============================================================

가능하면 테스트 코드는 프로젝트의 기존 Test 폴더/Assembly 구조를 따른다.

새 Test Assembly가 필요하면 Production Assembly 의존성을 불필요하게
복잡하게 만들지 않는다.

테스트용 임시 Scene/Data가 필요하면 명확한 Test 전용 위치에 둔다.

Production Inventory에 Test Workpiece가 자동 생성되는 식의 Test 흔적을
남기지 않는다.
