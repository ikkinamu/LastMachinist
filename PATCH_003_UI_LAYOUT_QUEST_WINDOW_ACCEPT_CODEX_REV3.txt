LAST MACHINIST — CODEX PATCH_003 REVISION 3
UI LAYOUT CONSISTENCY + QUEST ACCEPT FLOW

[IMPORTANT]
이 파일은 PATCH_003의 통합 수정본이다.
PATCH_003의 UI 버튼 위치/정렬 통일 작업에
'퀘스트를 수락해야 실제로 시작되는 흐름'을 추가한다.

PATCH_001 모따기, PATCH_002 Handwheel/영점 설정,
현재 정상인 측정 시스템과 기존 가공 로직은 유지한다.

============================================================
1. PATCH 목표
============================================================

A. UI 버튼 위치 / 정렬 / Anchor 규칙 통일
B. 퀘스트를 발견하거나 대화를 봤다는 이유만으로 즉시 시작하지 않게 변경
C. 수락 가능한 퀘스트는 별도 팝업이 아니라 기존 '퀘스트 창'에 등록
D. 플레이어가 퀘스트 창에서 해당 퀘스트를 선택하고 [수락]을 눌러야 Active 상태가 됨
E. 수락 전에는 QuestTracker, 목표 판정, 완료 조건이 진행되지 않게 함

============================================================
2. UI LAYOUT 기본 원칙
============================================================

- 같은 역할의 버튼은 같은 위치 규칙을 사용한다.
- 버튼마다 임의 Absolute Position을 하드코딩하지 않는다.
- 가능한 경우 공통 Container / Layout Group / Anchor를 사용한다.
- 해상도가 달라도 버튼 순서와 상대 위치가 유지되어야 한다.
- 기존 OnClick, 기능, 단축키는 보존한다.
- Player-Facing UI는 한국어를 유지한다.

AUDIT 대상:
- 선반 조작 UI
- X/Z Handwheel 및 영점 설정
- 공구 선택
- 카메라 전환
- 측정
- 퀘스트
- 확인/취소/닫기
- 팝업/모달
- 일시정지/설정

각 UI의 RectTransform, Anchor, Pivot, Size, Margin, Spacing,
부모 Container, Layout Group, Canvas Scaler, OnClick을 확인한다.

============================================================
3. 공통 버튼 위치 규칙
============================================================

[닫기]
- 패널/팝업 우측 상단
- 동일 Margin

[확인 / 취소]
- 팝업 하단의 공통 Container
- 프로젝트 전체에서 순서 통일
- 기존 다수 규칙이 없다면 [취소] [확인]

[카메라]
- 정면 / 평면 / 우측 / 등각을 하나의 Container로 관리
- 순서와 간격 고정

[선반]
- X 관련 조작은 X Handwheel Group
- Z 관련 조작은 Z Handwheel Group
- X/Z [영점 설정] 버튼은 각 Handwheel에서 동일한 상대 위치

[공구 선택]
- 공통 Tool Container에서 일정한 간격으로 정렬

[퀘스트]
- 수락 가능한 퀘스트는 기존 '퀘스트 창'의 목록에 표시한다.
- 별도의 Quest Offer 팝업/Modal을 새로 만들지 않는다.
- 퀘스트 창에서 Offered 상태의 퀘스트를 선택하면 상세 정보와 [수락] 버튼을 표시한다.
- [수락] 버튼은 퀘스트 창 내부의 고정된 Action 영역에 배치한다.
- 퀘스트를 바꿔 선택해도 [수락] 버튼 위치가 움직이지 않게 한다.

============================================================
4. QUEST STATE 구조
============================================================

현재 Quest 시스템을 먼저 AUDIT하고,
기존 상태 구조와 최대한 호환되게 다음 의미를 명확히 분리한다.

최소 개념:

Unavailable
→ 아직 제안되지 않음

Offered
→ 플레이어에게 퀘스트가 제안됨
→ 아직 시작되지 않음

Active
→ 플레이어가 [수락]을 눌러 실제 시작됨

Completed
→ 완료 조건 충족 및 완료 처리됨

기존 enum/state가 이미 있다면 무조건 새 enum을 중복 생성하지 말고
현재 구조에 Offered/Accepted 의미를 안전하게 반영한다.

============================================================
5. 퀘스트 창 등록
============================================================

NPC 대화, 이벤트, 의뢰 발견 등 기존 퀘스트 제안 조건이 발생해도
즉시 Active로 만들지 않는다.

대신:

Trigger / NPC Dialogue / Quest Discovery
→ 해당 Quest를 Offered 상태로 등록
→ 기존 '퀘스트 창'의 수락 가능 목록에 표시
→ 플레이어가 퀘스트 창을 열어 직접 확인
→ 퀘스트 선택
→ 상세 정보 표시
→ [수락] 선택

중요:
별도의 Quest Offer 팝업을 자동으로 띄우는 방식이 아니다.
퀘스트가 생기면 '퀘스트 창에 수락 가능한 의뢰가 추가되는 방식'이다.

퀘스트 창에서 Offered Quest를 선택했을 때 최소 표시:

- 퀘스트 제목
- 간단한 의뢰/목표 설명
- 현재 상태: 수락 가능
- [수락] 버튼

QUEST 01의 기존 스토리/내용 자체는 이번 PATCH에서 다시 쓰지 않는다.

============================================================
6. [수락] 동작
============================================================

플레이어가 퀘스트 창에서 Offered Quest를 선택한 뒤
[수락]을 눌렀을 때만:

Offered → Active

그리고 그 시점부터:

- QuestTracker 표시
- 현재 행동 목표 표시
- Quest Objective 판정 활성화
- 퀘스트 관련 상호작용/진행 판정 활성화
- 완료 조건 판정 활성화

수락 버튼을 누르기 전에 위 기능이 먼저 진행되면 안 된다.

============================================================
7. 수락 전 진행 차단
============================================================

Offered 상태에서는 퀘스트가 시작된 것이 아니다.

따라서 수락 전에 플레이어가 우연히:

- 펌프 축을 조사하거나
- 측정하거나
- 선반을 조작하거나
- 특정 아이템/오브젝트와 상호작용하거나
- 완료 조건에 해당하는 행동을 하더라도

퀘스트 Objective가 자동으로 진행/완료되어서는 안 된다.

Quest Objective 업데이트 전에 반드시
해당 Quest가 Active인지 확인한다.

개념:

if questState != Active:
    do not advance objective

단, 기존 시스템에서 수락 전 행동을 나중에 소급 인정하도록
명시적으로 설계된 항목이 있다면 그 기존 설계를 임의로 제거하지 않는다.
현재 QUEST 01에 그런 구조가 없다면 기본적으로 소급 진행하지 않는다.

============================================================
8. 퀘스트 창 닫기 / 미수락
============================================================

퀘스트 창을 닫거나 다른 퀘스트를 선택해도
Offered Quest는 실패하거나 사라지지 않는다.

기본 동작:

Offered
→ 퀘스트 창 닫기
→ Offered 유지
→ 나중에 퀘스트 창을 다시 열면 수락 가능 목록에 계속 표시
→ 언제든 [수락] 가능

이번 PATCH에서는 별도의 영구 거절 시스템을 만들지 않는다.

============================================================
9. 중복 수락 방지
============================================================

Active 상태인 퀘스트를 다시 수락할 수 없어야 한다.

- Active인데 Offer UI가 다시 뜨지 않음
- 수락 이벤트 중복 호출 없음
- QuestTracker 중복 생성 없음
- Objective 초기화가 두 번 실행되지 않음
- 보상/완료 이벤트 중복 없음

Completed 상태 역시 다시 수락되지 않게 한다.

============================================================
10. QUEST 01 적용
============================================================

MVP의 QUEST 01 '멈춰버린 펌프'에도 동일 흐름을 적용한다.

기존:
퀘스트 진입 조건 → 즉시 시작

목표:
퀘스트 진입 조건
→ QUEST 01을 Offered 상태로 등록
→ 퀘스트 창의 '수락 가능' 목록에 QUEST 01 표시
→ 플레이어가 퀘스트 창에서 QUEST 01 선택
→ 내용 확인
→ [수락]
→ QUEST 01 Active
→ 그때부터 펌프 축 관련 목표 진행

MVP의 최종 완료 조건인 펌프 복구 자체는 변경하지 않는다.

============================================================
11. QuestTracker
============================================================

QuestTracker는 번호형 전체 체크리스트로 바꾸지 않는다.
기존 원칙대로 '현재 해야 할 행동' 중심 표시를 유지한다.

수락 전:
- Active QuestTracker에 QUEST 01 목표를 표시하지 않는다.

수락 후:
- 현재 행동 목표를 표시한다.

Completed:
- 기존 완료 처리 흐름을 유지한다.

16. 필수 QUEST 테스트
============================================================

TEST Q01
QUEST 01 제안 조건 발생.

EXPECTED:
QUEST 01이 Offered 상태가 됨.
퀘스트 창의 수락 가능 목록에 표시됨.
자동으로 Active가 되지 않음.
별도 Quest Offer 팝업이 자동 표시되지 않음.

TEST Q02
퀘스트 창에서 QUEST 01을 선택만 하고 수락하지 않음.

EXPECTED:
상세 정보와 [수락] 버튼 표시.
Quest Objective 진행 없음.

TEST Q03
퀘스트 창에서 QUEST 01을 선택하고 [수락].

EXPECTED:
Offered → Active.
QuestTracker 표시.
첫 Objective 활성화.

TEST Q04
수락 전에 퀘스트 관련 행동 수행.

EXPECTED:
Objective 진행/완료 없음.

TEST Q05
수락 후 동일 행동 수행.

EXPECTED:
정상 진행.

TEST Q06
Offered 상태에서 퀘스트 창을 닫음.

EXPECTED:
Quest 실패 아님.
QUEST 01이 Offered 상태로 유지됨.
퀘스트 창을 다시 열면 수락 가능 목록에 계속 표시됨.

TEST Q07
Active 상태에서 다시 제안 Trigger 발생.

EXPECTED:
중복 Offer/수락/Tracker/Objective 초기화 없음.

TEST Q08
Completed 상태에서 Trigger 발생.

EXPECTED:
다시 수락되지 않음.

TEST Q09
QUEST 01을 정상 수락 후 기존 MVP 흐름으로 펌프 복구.

EXPECTED:
기존 완료 처리 정상.
