LAST MACHINIST — VERTICAL SLICE PHASE 03

WORKPIECE INSTANCE & INVENTORY v0.1 — CODEX DEVELOPMENT SPEC

0. 목표

Phase 02의 조사 → 회수를 실제 인벤토리로 연결한다.

핵심:
탐색 → 공작물 조사 → 회수 → 개별 WorkpieceInstance 저장 → 작업장 복귀 → 인벤토리에서 확인

단순 철봉 ×3 방식이 아니라, 같은 종류/규격의 공작물도 각각 고유한 상태를
가진 개별 아이템으로 저장한다.

1. BASELINE

유지: - Phase 01 탐색 탭/지도/1인칭 이동/복귀 - Phase 02 Interaction
Ray/특성 창/회수/Session Recovery List - MVP 및 PATCH_001~003 기존 기능

기존 기능을 재작성하지 말고 필요한 연결만 확장한다.

2. 데이터 계층

MaterialDefinition

재료 종류 자체의 공통 특성. - MaterialId - DisplayName -
HardnessRating - StrengthRating - MachinabilityRating -
CorrosionResistanceRating

게임플레이 Rating 범위는 0~100. - 경도: 높을수록 단단함 - 강도: 높을수록
강함 - 절삭성: 높을수록 가공하기 쉬움 - 내식성: 높을수록 부식에 강함

실제 공학 물성값과 혼동하지 않는다. 실제 물성은 향후 별도 필드로 확장
가능하게 한다.

WorkpieceDefinition

공작물 종류/기본 형상. - WorkpieceDefinitionId - DisplayName -
ShapeType - NominalDimensions - MaterialDefinition reference -
BaseInspectionProperties - InventoryIcon(optional)

예: 원형 봉재 / Ø50 / 길이 300

WorkpieceInstance

플레이어가 실제로 발견하고 회수한 그 한 개의 공작물. - InstanceId
(unique) - WorkpieceDefinitionId - Material reference -
ConditionProperties - IdentificationState - AcquiredRegionId(optional) -
AcquiredSessionId(optional)

같은 Definition이어도 InstanceId가 다르면 서로 다른 공작물이다.

3. 공작물 상태 특성

WorkpieceInstance마다 개별 상태 점수를 저장한다. 모든 상태 점수는
높을수록 좋은 상태로 통일한다.

초기 핵심 4개: - 부식 상태 (CorrosionCondition) - 표면 상태
(SurfaceCondition) - 형상 건전성 (ShapeIntegrity) - 결함 건전성
(DefectIntegrity)

범위: 0~100

의미: - 부식 상태 100 = 녹/부식 거의 없음, 0 = 심각한 부식 - 표면 상태
100 = 손상 거의 없음, 0 = 심각한 긁힘/찍힘/손상 - 형상 건전성 100 =
휨/변형 거의 없음, 0 = 심각한 변형 - 결함 건전성 100 = 눈에 띄는 결함
거의 없음, 0 = 심각한 결함

향후 오염, 잔존 가공여유, 열손상 등을 확장할 수 있게 하되 Phase 03에서
과도하게 늘리지 않는다.

4. 개체별 차이

같은 ROUND_BAR_50 두 개도 서로 다른 상태를 가질 수 있어야 한다.

예: A: 부식 82 / 표면 64 / 형상 95 / 결함 91 B: 부식 43 / 표면 88 / 형상
71 / 결함 84

두 개를 수량 Stack 하나로 합쳐 상태 데이터를 잃으면 FAIL.

테스트 상태값은 Scene 지정, Spawn Data, 제한적 생성 중 현재 구조에 맞는
방법을 사용한다. 완성형 랜덤 루팅 시스템은 만들지 않는다.

5. 종합 상태 점수

인벤토리 비교용 OverallConditionScore를 제공할 수 있다.

초기: OverallConditionScore = (부식 + 표면 + 형상 + 결함) / 4

단, 종합점수는 정렬/요약용이다. 개별 상태 특성은 반드시 그대로 보존한다.

종합점수가 높다고 모든 가공 목적에 무조건 적합한 구조로 만들지 않는다.
향후 가공 시스템은 각 특성을 개별 참조할 수 있어야 한다.

6. 재료 식별 상태

최소: - Unknown - Identified

Phase 03에서는 재료 식별 과정 자체를 구현하지 않는다.

Unknown이면 내부 MaterialId가 존재해도 UI에 정답을 공개하지 않는다.

예: 재료: 미식별 경도: ??? 강도: ??? 절삭성: ??? 내식성: ???

Identified 상태에서만 허용된 재료 정보/특성을 표시할 수 있다.

7. 회수 → Player Inventory

Phase 02 [회수] 흐름을 확장한다.

1.  조사 대상 WorkpieceInstance 확인
2.  InstanceId 유효성 확인
3.  Player Inventory에 개별 Instance 저장
4.  Session Recovery List에도 기록
5.  저장 성공 후 월드 오브젝트 제거/비활성
6.  특성 창 닫기
7.  탐색 복귀

Inventory 저장 실패 시 월드 오브젝트를 먼저 제거하면 안 된다. 동일
InstanceId 중복 저장을 방지한다.

8. Player Inventory

최소 기능: - Add WorkpieceInstance - Remove WorkpieceInstance (향후
연결용) - Find by InstanceId - List all Workpieces - 중복 InstanceId
방지

같은 Definition의 공작물도 개별 Instance로 저장한다. 작업장 복귀 후에도
유지되어야 한다.

9. 인벤토리 UI

기존 Main/Workshop UI를 AUDIT한 뒤 [인벤토리] 탭을 추가한다.

목록: - 공작물 이름 - 간단한 종합 상태 점수(optional)

상세: - 공작물 이름 - 형상/규격 - 재료 식별 상태 - 재료 특성 - 공작물
상태 특성 - 종합 상태 점수

예: 원형 봉재 Ø50

재료: 미식별

[재료 특성] 경도: ??? 강도: ??? 절삭성: ??? 내식성: ???

[공작물 상태] 부식 상태: 82 표면 상태: 64 형상 건전성: 95 결함 건전성:
91

종합 상태: 83

같은 이름의 공작물이 여러 개라도 각각 선택 가능해야 한다. InstanceId
원문을 플레이어에게 반드시 표시할 필요는 없다.

10. Save / Load

기존 Save/Load 시스템을 먼저 AUDIT한다. 새 독립 Save System을 중복
생성하지 않는다.

최소 저장: - InstanceId - WorkpieceDefinitionId - Material
reference/ID - ConditionProperties - IdentificationState

Save/Load 후 개별 공작물과 상태 점수가 동일하게 복원되어야 한다.

11. Phase 02 조사 정보와 분리

탐색 특성 창은 관찰 가능한 정보 중심이다. Inventory는 저장된 Instance
데이터를 표시한다.

Inspection Data와 Condition Data를 무조건 하나로 합치지 않는다. 관찰
문구와 게임 내부 수치 데이터는 목적이 다르다.

Unknown 재료의 내부 정답은 어느 UI에서도 자동 공개하지 않는다.

12. 향후 가공 연결 대비

Phase 03에서 실제 가공 재료 선택은 구현하지 않는다.

향후:
Inventory WorkpieceInstance 선택 → 가공 재료 지정 → Instance 상태를 가공 시스템이 참조

가 가능하도록 데이터/API만 확장 가능하게 한다.

16. PASS

-   MaterialDefinition / WorkpieceDefinition / WorkpieceInstance 분리
-   재료 특성과 공작물 현재 상태 분리
-   동일 종류 공작물을 개별 Instance로 저장
-   상태 0~100, 높을수록 좋은 상태로 통일
-   개별 상태값 보존
-   종합 상태 점수 계산
-   회수 시 Player Inventory 저장
-   작업장 복귀 후 유지
-   인벤토리에서 개별 공작물 비교 가능
-   Unknown Material 정답 숨김
-   Save/Load 후 동일 복원
-   기존 시스템 회귀 없음
-   Console Error 없음

17. FAIL

-   같은 종류를 단순 Stack으로 합쳐 개체 상태 소실
-   재료 특성과 개체 상태 혼합
-   모든 공작물이 같은 상태값 공유
-   점수 방향 혼재
-   종합점수만 저장하고 개별 특성 삭제
-   Unknown 재료 정답 노출
-   Inventory 저장 실패 전에 월드 아이템 삭제
-   Instance 중복 저장
-   작업장 복귀/SaveLoad 시 Inventory 소실 또는 점수 초기화
-   기존 탐색/가공/측정/Quest 손상
-   범위 밖 가공 결과/완성형 식별 시스템 임의 구현

19. 완료 정의

같은 종류의 공작물 두 개를 탐색에서 회수했을 때 각각 별도의
WorkpieceInstance로 인벤토리에 저장되고, 서로 다른 녹/표면/형상/결함
상태 점수를 유지해야 한다.

작업장 복귀 후 [인벤토리]에서 각각 선택하여 비교할 수 있어야 하며,
미식별 재료의 내부 정답은 노출되지 않아야 한다.

Save/Load 이후에도 각 Instance와 상태가 그대로 유지되면 Phase 03 완료다.
