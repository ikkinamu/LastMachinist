LAST MACHINIST — VERTICAL SLICE

CROSS-PHASE REV 02 — TITLE / SAVE / CONTINUE / SYSTEM MENU / EXIT FLOW

0. 목적

빌드에서 정상적인 시작, 이어하기, 저장, ESC 시스템 메뉴, 종료 흐름을
제공한다. 기존 MVP/PATCH/Phase 문서는 재작성하지 않고 현재 시스템을
AUDIT한 뒤 확장한다. 프롤로그 컷씬 자체는 이번 REV의 범위가 아니다.

핵심 변경: - 세이브 없음: [시작] [설정] [게임 종료] - 세이브 있음:
[계속하기] [새 게임] [설정] [게임 종료] - 일반 Player-facing [불러오기]
선택 과정 제거 - [계속하기] = Auto/Manual 중 가장 최근의 유효한 Save
자동 로드 - 최신 Save 손상 시 이전 정상 Save로 폴백 - 수동 저장 유지 +
자동 저장 추가 - ESC 메뉴 [계속하기] [저장] [설정] [게임 종료] - 종료
확인 [취소] [저장 후 종료] [저장하지 않고 종료] - 새 게임은 기존 진행
초기화 확인 필수

1. 구현 전 AUDIT

Codex는 먼저 다음을 확인한다. - Title/Boot/Workshop Scene 진입 구조 -
기존 SaveSystem, SaveData, Save Slot/파일 구조 - 현재
[저장] [불러오기] [닫기] UI와 호출 경로 - Quest/Workpiece/Region/Unlock
저장 데이터 - ESC 입력, Modal UI, Cursor Lock, Input Context -
Application.Quit 관련 코드 - 기존 ActionButtonGroup/Anchor/Layout 규칙

기존 SaveSystem이 있으면 반드시 확장한다. 병렬 SaveManager/SaveSystem을
새로 만들어 두 시스템이 공존하면 FAIL.

2. 타이틀 화면

세이브 없음: [시작] [설정] [게임 종료]

[시작]은 New Game Entry를 호출한다. 향후 프롤로그가 구현되면 이 진입점에
연결한다.

유효한 세이브 있음: [계속하기] [새 게임] [설정] [게임 종료]

[계속하기]는 Save 선택창을 띄우지 않는다. 가장 최근의 정상 Save를 자동
탐색하여 로드한다.

[새 게임]은 반드시 확인창을 표시한다.

예: 현재 진행 상황을 초기화하고 새 게임을 시작하시겠습니까?
[취소] [새 게임 시작]

확인 전에는 기존 Save를 삭제/초기화하지 않는다.

3. 최신 정상 Save 자동 선택

개념: GetAllSaveCandidates() → Auto + Manual 후보 수집 → 최신 순 정렬 →
Validity Check → 첫 정상 Save Load

예: Manual C 22:40 Auto B 22:35 Auto A 22:20

C 정상 → C C 손상 → B C/B 손상 → A

모든 후보가 손상된 경우: - 크래시 금지 - 정상 Save를 찾지 못했다는
안내 - 타이틀 유지 및 새 게임 선택 가능

4. Save Metadata / Validity

기존 구조를 우선한다. 필요 시 다음 메타데이터를 확장할 수 있다. -
SaveId - SaveType: Auto / Manual - Timestamp - SaveFormatVersion -
GameVersion/BuildVersion - Validation 정보 - optional checksum/hash -
optional completion marker

파일 수정 시간이 최신이라는 이유만으로 손상 Save를 우선 Load하지 않는다.

5. 자동 저장

수동 저장은 유지하고 Auto Save를 추가한다.

권장 안전 Trigger: - Main Quest 수락/완료 - Repeatable Quest 수락/완료 -
탐색 출발 - 탐색에서 작업장으로 정상 복귀 - 공작물 회수 완료 - 중요
장비/핵심 아이템 획득 - 주요 Progression Unlock - 작업장 정상 복귀

금지: - 매 프레임 저장 - Handwheel 이동마다 저장 - Geometry 변경 매 순간
저장 - 측정 UI 클릭마다 저장 - SaveSystem이 완전한 중간복원을 지원하는지
확인하지 않고 가공 도중을 무조건 Auto Save

6. Rolling Backup

Auto Save는 최소 2세대의 복구 가능한 백업을 유지한다.

권장: AutoSave_0 = 최신 AutoSave_1 = 직전 AutoSave_2 = 선택적 추가

최신 Auto Save가 손상되어도 직전 정상 Save를 사용할 수 있어야 한다.
Manual Save와 Auto Save 모두 [계속하기] 후보가 된다.

7. 안전한 저장

권장 atomic-ish 흐름: 1. 임시 파일에 SaveData 작성 2. 직렬화 성공 확인
3. 최소 유효성 검사 4. 완료 마커/상태 확인 5. 기존 최신 Save와 교체 또는
Rolling 6. 실패 시 기존 정상 Save 보존

프로젝트의 기존 안전 저장 방식이 있으면 재사용한다.

8. 수동 저장

수동 [저장]은 유지한다. 기존 SaveSystem을 사용한다. 성공/실패를 정확히
표시한다. 가장 최근의 정상 Manual Save라면 다음 [계속하기]에서 해당
Save가 로드된다.

9. Player-facing 불러오기 제거

기존 [저장] [불러오기] [닫기] 구조는 재검토한다.

기본: [저장] [닫기]

일반 플레이에서는 Save Slot을 직접 골라 Load할 필요가 없다. Player
Flow는 타이틀 [계속하기] 중심으로 통일한다.

개발/디버그용 Load 기능은 Player-facing UI와 분리하여 유지 가능하다.

10. ESC 시스템 메뉴

Gameplay 중 ESC: [계속하기] [저장] [설정] [게임 종료]

-   계속하기: 메뉴 닫고 복귀
-   저장: Manual Save
-   설정: 기존/향후 Settings 진입점
-   게임 종료: Exit Confirmation

ESC 재입력: - 하위 Modal이 없으면 메뉴 닫기 - 하위 Modal이 있으면 기존
UI 정책에 따라 최상위 Modal부터 처리

11. ESC 입력 상태

메뉴 Open: - World Movement 차단 - Camera Look 차단 - Machining Input
차단 - World Interaction 차단 - UI Input 허용 - Cursor 표시/Unlock

메뉴 Close: 이전 Gameplay Context에 맞게 정확히 복원한다.

탐색에서 Resume → WASD/Mouse Look 정상 가공에서 Resume → Machining Input
정상

12. 게임 종료 확인

Gameplay의 [게임 종료]는 즉시 Quit하지 않는다.

게임을 종료하시겠습니까? [취소] [저장 후 종료] [저장하지 않고 종료]

취소: 확인창 닫고 시스템 메뉴 복귀.

저장 후 종료: 1. 안전한 Save 실행 2. 성공 확인 3. 성공 시 Quit 실패하면
Quit하지 않고 실패 안내.

저장하지 않고 종료: 현재 미저장 변경은 버리고 기존 정상 Save는 보존한 채
Quit.

13. 타이틀 종료

타이틀 [게임 종료]: 게임을 종료하시겠습니까? [취소] [종료]

14. Unity Build / Editor

Player Build: Application.Quit() 또는 프로젝트의 동등한 정상 종료 경로.

Unity Editor: Application.Quit만으로 Play Mode가 멈추지 않는 문제를
처리한다. 필요 시 Editor-only 분기 사용:
EditorApplication.isPlaying = false

UnityEditor 의존성이 Player Build에 포함되면 FAIL. 기존 Assembly 구조를
먼저 AUDIT한다.
