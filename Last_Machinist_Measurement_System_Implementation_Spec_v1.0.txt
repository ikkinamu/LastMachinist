LAST MACHINIST — MEASUREMENT SYSTEM IMPLEMENTATION SPEC v1.0
작성 기준: 2026-09-12
적용 대상: Last Machinist MVP / Unity + Codex
우선순위: 매우 높음 / 핵심 게임 시스템

============================================================
0. 이 문서의 목적
============================================================

이 문서는 Last Machinist의 "측정" 시스템을 구현하기 위한 절대 기준이다.

측정 시스템은 단순히 치수를 숫자로 보여주는 기능이 아니다.
측정은 게임의 핵심 플레이 루프 중 하나이며,
플레이어가 실제로 "눈금을 보고, 읽고, 판단하고, 기록하는" 행위 자체가 게임플레이다.

이 문서를 읽고도
"측정 버튼을 누르면 39.80 mm가 뜬다"
같은 구현을 하면 실패다.

가장 중요한 한 문장:

플레이어에게 정답 숫자를 보여주지 않는다.
플레이어는 버니어의 눈금을 직접 보고 값을 읽어야 한다.

============================================================
1. 측정 시스템의 핵심 철학
============================================================

Last Machinist의 측정은 다음 구조다.

[공작물의 실제 형상]
        ↓
TrueDimension
        ↓
측정기 특성 반영
        ↓
InstrumentReading
        ↓
버니어의 물리적 모양과 눈금 위치로 표현
        ↓
플레이어가 직접 눈금을 읽음
        ↓
직접 숫자 입력
        ↓
RecordedMeasurement

절대로 다음처럼 만들지 않는다.

[공작물 클릭]
→ "39.80 mm"
→ 확인 버튼

이것은 측정 게임이 아니라 숫자 표시창이다.

============================================================
2. 세 가지 값은 절대 합치지 않는다
============================================================

반드시 아래 3개를 분리한다.

1. TrueDimension
2. InstrumentReading
3. RecordedMeasurement

----------------------------------------
2.1 TrueDimension
----------------------------------------

게임 내부의 실제 공작물 치수.

예:

현재 공작물 실제 지름:
39.80 mm

그러면:

TrueDimension = 39.80

이 값은 Workpiece Geometry에서 계산한다.
플레이어는 이 값을 직접 볼 수 없다.
일반 게임 UI에 절대 표시하지 않는다.

허용:
- Editor
- Development Build Debug Panel
- 자동화 테스트

금지:
- 일반 HUD
- MeasurementPage
- VernierView
- Quest UI
- WorkMemo

----------------------------------------
2.2 InstrumentReading
----------------------------------------

측정기가 실제로 표현해야 할 값.

MVP에서는 복잡한 계측 오차를 생략할 수 있으므로
초기에는 다음처럼 동일할 수 있다.

TrueDimension = 39.80
InstrumentReading = 39.80

하지만 데이터 구조는 반드시 분리한다.

향후:
TrueDimension = 39.80
InstrumentReading = 39.82

같은 시스템을 확장할 수 있어야 한다.

InstrumentReading은 숫자 텍스트로 플레이어에게 보여주는 값이 아니다.
이 값은 버니어의:
- 죠 간격
- 슬라이더 위치
- 본척 위치
- 부척 위치
- 눈금 정렬
을 계산하기 위한 내부 입력값이다.

----------------------------------------
2.3 RecordedMeasurement
----------------------------------------

플레이어가 직접 눈금을 읽고 입력한 값.

예:
TrueDimension = 39.80
InstrumentReading = 39.80

플레이어가 눈금을 잘못 읽음.
플레이어 입력:
39.30

그러면:
RecordedMeasurement = 39.30

게임은 자동으로 다음 행동을 하면 안 된다.
- "틀렸습니다."
- "정답은 39.80입니다."
- 39.30 → 자동으로 39.80 수정

플레이어가 잘못 읽은 기록도 그대로 저장한다.

============================================================
3. 측정이 실제 플레이에서 어떻게 진행되는가
============================================================

STEP 1. 플레이어가 측정 모드에 들어간다.
STEP 2. 측정할 대상 공작물을 확인한다.
STEP 3. 측정할 위치를 선택한다.
STEP 4. MeasurementPoint가 Workpiece Geometry를 참조하여 실제 치수를 계산한다.
STEP 5. TrueDimension을 얻는다.
STEP 6. 측정기 모델이 InstrumentReading을 생성한다.
STEP 7. 버니어 캘리퍼스가 InstrumentReading에 맞는 위치로 움직인다.
STEP 8. 플레이어 화면에는 버니어 눈금만 보인다.
STEP 9. 플레이어가 눈금을 직접 읽는다.
STEP 10. 플레이어가 빈 입력칸에 직접 숫자를 입력한다.
STEP 11. [기록] 버튼을 누른다.
STEP 12. 입력값을 RecordedMeasurement로 저장한다.
STEP 13. WorkMemo / 검사표 / Quest 진행에 필요한 경우 기록 사실만 전달한다.

중요:
정답 숫자는 STEP 1~13 어디에서도 플레이어에게 자동 공개하지 않는다.

============================================================
4. MeasurementPoint의 정확한 의미
============================================================

MeasurementPoint는 "정답 숫자를 반환하는 버튼"이 아니다.
MeasurementPoint는 "플레이어가 측정기를 어느 위치에 대는가"를 정의하는 선택 지점이다.

예:
PumpShaftBroken
- L1_Diameter
- L1_Length
- L2_Diameter
- L2_Length
- L3_Diameter
- L3_Length

L1_Diameter를 선택하면:
1. L1 위치를 시각적으로 강조
2. 해당 위치의 실제 Geometry를 읽음
3. 현재 지름을 계산
4. 버니어가 해당 지름만큼 벌어짐
5. 플레이어가 눈금을 읽음

절대로:
L1_Diameter 선택
→ 40.00 mm 출력

이렇게 만들지 않는다.

============================================================
5. 버니어 캘리퍼스는 장식 UI가 아니다
============================================================

VernierView는 단순 이미지가 아니다.
측정값에 따라 실제로 움직여야 한다.

필수 구성:
- 고정 죠
- 이동 죠
- 본척(Main Scale)
- 부척(Vernier Scale)
- 슬라이더
- 측정 대상 표시
- 현재 접촉 상태

InstrumentReading이 바뀌면 버니어 모양도 바뀌어야 한다.

예:
InstrumentReading = 37.60
→ 이동 죠가 37.60에 해당하는 위치까지 이동
→ 부척이 본척 위에서 실제 읽을 수 있는 위치에 배치
→ 눈금 정렬이 37.60에 해당해야 함

InstrumentReading = 42.20
→ 이전과 다른 위치로 이동
→ 눈금 정렬도 바뀜

============================================================
6. 버니어 눈금 구현 원칙
============================================================

MVP에서는 하나의 버니어 사양을 고정 사용한다.
현실 특정 제품의 훈련기를 복제할 필요는 없지만, 게임 내 눈금은 일관되고 판독 가능해야 한다.

반드시 다음을 만족한다.
1. 본척이 있다.
2. 부척이 있다.
3. 측정값에 따라 부척 위치가 달라진다.
4. 특정 부척 눈금이 본척 눈금과 정렬된다.
5. 플레이어가 눈으로 값을 추론할 수 있다.
6. 정답 숫자를 옆에 표시하지 않는다.

============================================================
7. 버니어 표시값 계산 흐름
============================================================

권장 구조:
MeasurementService
→ GetTrueDimension()
→ MeasurementInstrumentModel
→ GetInstrumentReading()
→ VernierDisplayModel
→ VernierRenderer

VernierDisplayModel 예:
- MainScaleBase
- SliderPosition
- VernierOffset
- AlignedVernierIndex
- JawOpening

화면에서는 이 DisplayModel을 사용한다.
UI가 직접 TrueDimension을 읽어 텍스트로 출력하지 않는다.

============================================================
8. MeasurementPage UI 구성
============================================================

상단:
- 제목: "측정"
- 대상: "마모된 펌프 축"

측정 위치 패널:
[L1 직경]
[L1 길이]
[L2 직경]
[L2 길이]
[L3 직경]
[L3 길이]

중앙:
- 확대된 VernierView
- 본척
- 부척
- 죠
- 선택한 측정 위치 강조

하단:
읽은 값 입력
[              ] mm

[기록]
[다시 측정]
[기록 목록]
[돌아가기]

가공 중이라면:
[가공으로 돌아가기]

중요:
입력칸은 항상 플레이어가 직접 입력한다.
MeasurementPoint를 선택했다고 자동으로 채워지면 실패다.

============================================================
9. 측정 화면의 UI 우선순위
============================================================

MeasurementPage에서 가장 중요한 것은 버니어다.

우선순위:
1. 버니어 눈금
2. 측정 대상 위치
3. 입력칸
4. 기록 버튼
5. 측정 위치 선택
6. 퀘스트 목표
7. 기타 HUD

절대 금지:
- 거대한 퀘스트창이 버니어를 가림
- 버니어 위에 튜토리얼 창 표시
- 숫자 정답 텍스트를 눈금 옆에 표시
- 입력칸에 자동 정답 입력
- 일반 HUD가 눈금 영역 침범

============================================================
10. 측정 모드 진입 조건
============================================================

선반에서 측정하려면:
- Workpiece가 존재
- 측정 가능한 MeasurementPoint 존재
- 버니어 보유
- Quest/게임 상태가 측정 허용
- 주축 정지

주축이 회전 중이면 측정 모드 진입 금지.

한국어 안내 예:
"주축이 회전 중입니다."
"측정하려면 먼저 주축을 정지하세요."

============================================================
11. 고장 펌프 축 측정
============================================================

정상 원래 형상:
전체 길이 100 mm
L1 = Ø40 × 30
L2 = Ø50 × 40
L3 = Ø40 × 30

고장품:
- L1 정상에 가까움
- L2 정상에 가까움
- L3 직경 마모
- L3 길이 방향 마모

플레이어가 L3를 재면 "원래 Ø40 × 30"을 보여주면 안 된다.
버니어는 오직 현재 마모되어 남아 있는 실제 치수만 표현한다.

============================================================
12. 첫 퀘스트에서 플레이어가 배우는 사고 과정
============================================================

목표:
"측정값 = 설계값"이 항상 성립하지 않는다는 것을 직접 이해하게 한다.

진행:
1. L1 측정
2. L2 측정
3. L3 측정
4. L3가 반대쪽과 다름을 확인
5. 시각적 마모 흔적 확인
6. 전체 형상 대칭성 관찰
7. L1이 L3의 원래 대응 형상일 가능성 판단
8. 전체 길이 정보 및 형상을 함께 판단
9. 원래 L3 형상을 추론

버니어:
"지금 이 부품이 현재 어떻게 되어 있는지"

WorkMemo/관찰:
"이 부분은 마모된 것 같다"

플레이어:
"그러면 원래 형상은 반대편과 같았을 가능성이 높다"

이것이 핵심 게임플레이다.

============================================================
13. WorkMemo와 측정 연동
============================================================

WorkMemo는 정답 공개창이 아니다.

처음:
펌프 축
도면 없음

L1 측정 후:
플레이어가 기록한 값만 표시 가능.

예:
L1 직경
기록: 40.0

이 값은 RecordedMeasurement이다.
실제 내부 치수와 자동 동기화하지 않는다.

L3 측정 후:
관찰:
- 마모 흔적 있음
- 반대쪽과 형상이 다름

추론 완료 전에는:
"원래 L3 = Ø40 × 30"
자동 표시 금지.

ShapeInferred 이후에만:
추정 원형
L1 Ø40 × 30
L2 Ø50 × 40
L3 Ø40 × 30
전체 100

을 표시할 수 있다.

============================================================
14. RecordedMeasurement 데이터
============================================================

MeasurementRecord 예:
- RecordId
- WorkpieceInstanceId
- MeasurementPointId
- InstrumentId
- RecordedValue
- Timestamp(optional)
- QuestId(optional)

RecordedValue는 플레이어 입력값이다.
MeasurementRecord에 TrueDimension을 정답처럼 복사하지 않는다.

============================================================
15. 측정 후 가공 루프
============================================================

선반 가공
↓
주축 정지
↓
측정
↓
현재 구간 선택
↓
버니어 눈금 확인
↓
플레이어 직접 판독
↓
값 입력
↓
가공 화면 복귀
↓
더 깎을지 판단
↓
추가 가공
↓
재측정

게임이 "0.2 mm 더 깎으세요"처럼 정답을 대신 판단해주지 않는다.
플레이어가 자기 기록을 보고 판단한다.

============================================================
16. 최종 검사
============================================================

가공 완료 후 필요한 MeasurementPoint를 다시 측정한다.
플레이어가 값을 직접 기록한다.

PartEvaluator는 RecordedMeasurement가 아니라 실제 Workpiece Geometry를 기준으로 기능 판정한다.

예:
플레이어 기록: Ø40.00
실제 Geometry: Ø38.50

PartEvaluator는 Ø38.50을 평가한다.
RecordedMeasurement는 "플레이어가 무엇이라고 판단했는가"를 나타낼 뿐이다.

============================================================
17. 잘못 읽었을 때
============================================================

실제 39.80
플레이어 입력 39.30

[기록]

결과:
RecordedMeasurement = 39.30

즉시 경고 없음.
정답 공개 없음.
자동 수정 없음.

잘못된 측정은 이후 플레이어 판단에 영향을 줄 수 있다.
이것이 의도된 게임플레이다.

============================================================
18. 첫 버니어 획득 튜토리얼
============================================================

박성철:
"……뭘로 쟀나?"

주인공이 금속 자를 보여줌.

박성철:
"……."
"에헤이~."
"그건 네 삼촌이 그런 데 쓰라고 남긴 게 아닐 텐데."

시스템:
[낡은 버니어 캘리퍼스를 획득했습니다.]

박성철:
"여기가 본척이고, 이쪽 움직이는 게 부척이야."
"본척에서 먼저 보고, 부척 눈금 중 맞는 곳을 찾게."

첫 1회에는 [본척], [부척] 시각 라벨을 허용한다.
그러나 "현재 값은 39.80입니다" 같은 정답 표시는 금지한다.

============================================================
19. 측정 위치 시각화
============================================================

MeasurementPoint 선택 시 플레이어가 어디를 재고 있는지 명확해야 한다.

L1 직경:
- L1 구간 강조
- 버니어 죠가 해당 외경을 잡는 그림
- 나머지 구간 약간 어둡게

L2 길이:
- L2 양 끝 기준선 표시
- 현재 선택 구간 강조

플레이어가 "이 치수가 어느 부분인지" 헷갈리지 않게 한다.

============================================================
20. 직경 측정과 길이 측정 구분
============================================================

MeasurementPoint.Type 예:
- OuterDiameter
- Length

직경은 외경 측정 표현을 사용한다.
길이는 선택된 두 기준점 사이 길이를 측정하는 표현을 사용한다.

둘을 하나의 의미 없는 공통 버튼으로 뭉개지 않는다.

============================================================
21. 금속 자와 버니어의 차이
============================================================

금속 자:
- 대략적인 길이 확인
- 정밀 측정 부적합
- progression 연출

버니어:
- 주요 외경/길이 측정
- 본척/부척 직접 판독
- 직접 기록

금속 자가 버니어와 같은 정밀 측정 기능을 제공하면 안 된다.

============================================================
22. UI 한국어 강제
============================================================

Player-facing 표시 언어는 한국어.

Measurement → 측정
Target → 대상
Measurement Point → 측정 위치
Record → 기록
Records → 기록 목록
Back → 돌아가기
Return to Machining → 가공으로 돌아가기
Main Scale → 본척
Vernier Scale → 부척
Read Value → 읽은 값

코드 내부 영어 식별자는 사용 가능하지만 그대로 UI에 출력하지 않는다.

============================================================
23. Quest State 연동
============================================================

InspectingBrokenShaft:
허용:
- 버니어 사용
- L1/L2/L3 MeasurementPoint 선택
- 기록
- WorkMemo 확인
- 인벤토리 확인

금지:
- 새 봉재 가공 시작

31. 첫 퀘스트 완전 예시

측정
대상: 마모된 펌프 축

[L1 직경]
[L1 길이]
[L2 직경]
[L2 길이]
[L3 직경]

게임 내부에서 L1 실제 지름 계산.
버니어 죠 이동.
본척/부척 표시.

플레이어가 눈금 읽고 40.0 입력.

L1_Diameter = 40.0

추론 완료 후에만:
추정 원형
L1 Ø40 × 30
L2 Ø50 × 40
L3 Ø40 × 30
전체 길이 100

표시 가능.

34. Codex 작업 지시
============================================================

Codex는 측정 시스템 수정/구현 시 반드시:

1. 기존 Measurement 관련 파일을 모두 확인한다.
2. 현재 구현과 이 문서의 차이를 목록화한다.
3. 숫자 자동 표시 여부를 찾는다.
4. TrueDimension / InstrumentReading / RecordedMeasurement 분리 여부 확인.
5. VernierView가 실제 측정값에 따라 움직이는지 확인.
6. Debug 값이 일반 UI에 노출되는지 확인.
7. MeasurementPoint가 올바른 Geometry를 참조하는지 확인.
8. 한국어 UI인지 확인.
9. 수정 계획 작성.
10. 구현.
11. 컴파일 오류 확인.
12. TEST A~H 수행.
13. 각 테스트 결과를 PASS/FAIL로 보고.
14. FAIL 하나라도 있으면 "측정 시스템 완료"라고 보고하지 않는다.
