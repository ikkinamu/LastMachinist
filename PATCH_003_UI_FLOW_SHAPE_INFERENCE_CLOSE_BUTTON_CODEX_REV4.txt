LAST MACHINIST — CODEX PATCH_003 REVISION 4
UI FLOW / MATERIAL SELECTION / SHAPE INFERENCE TABS / CLOSE BUTTON POSITION

[IMPORTANT]
이 파일은 PATCH_003 REV3의 후속 수정 작업지시서다.
새 PATCH 번호를 만들지 않는다.

REV3에서 확정한 다음 사항은 유지한다.

- 프로젝트 전체 UI 버튼 위치/정렬 규칙 통일
- 수락 가능한 퀘스트는 별도 팝업이 아니라 기존 퀘스트 창에 표시
- 퀘스트 창에서 [수락]해야 Active 상태가 됨
- 수락 전 Objective 진행 금지
- 기존 선반/측정/Handwheel/영점/모따기 기능 보존

이번 REV4에서는 다음 3가지를 추가/수정한다.

1. 작업 준비 순서: 가공 방식 선택 → 재료 선택
2. 메모 탭의 형상 추론: 대상 형상 구성에 따라 추론 탭 생성
3. 닫기 버튼: 우측 상단이 아니라 [저장] [불러오기] 옆으로 이동

============================================================
1. 작업 준비 FLOW
============================================================

작업 준비 순서를 다음과 같이 고정한다.

가공 방식 선택
→ 재료 선택
→ 선택 내용 확정
→ 해당 가공 작업 진입

재료 선택을 가공 방식 선택보다 먼저 요구하지 않는다.

중요:
'가공 방식'의 구체적인 선택지는 현재 프로젝트에 이미 존재하는
가공 방식/작업 선택 구조를 그대로 사용한다.
이번 PATCH에서 임의로 새로운 가공 방식을 추가하지 않는다.

============================================================
2. 가공 방식 선택 전 재료 선택 금지
============================================================

가공 방식이 아직 선택되지 않았다면 재료 선택 단계로 넘어가지 않는다.

가능한 구현 방식:

- 재료 선택 UI 비활성
또는
- 재료 선택 UI를 아직 표시하지 않음

현재 UI 구조에 가장 자연스러운 방식을 사용한다.

하지만 플레이어가 보기에 반드시 다음 순서가 명확해야 한다.

STEP 1. 가공 방식 선택
STEP 2. 재료 선택

재료를 먼저 선택한 뒤 가공 방식을 고르는 흐름이면 FAIL이다.

============================================================
3. 재료 선택
============================================================

가공 방식이 확정된 후 재료 선택 UI를 활성화/표시한다.

기존 재료 데이터와 선택 로직이 있다면 그대로 재사용한다.

이번 PATCH에서:

- 재료 시스템 전면 재작성 금지
- 임의의 새 재료 추가 금지
- 기존 재료 스탯/물성 변경 금지

목표는 선택 순서와 UI 흐름을 바로잡는 것이다.

============================================================
4. 메모 탭 — 형상 추론 기본 원칙
============================================================

메모의 '형상 추론' 영역은
QUEST 01 전용으로 고정된 L1/L2/L3 같은 탭을 하드코딩하지 않는다.

대상 부품의 형상 구성에 따라 필요한 형상 추론 탭을 만든다.

즉:

대상 부품 형상 데이터
→ 추론 가능한 형상/구간 파악
→ 해당 형상에 대응하는 추론 탭 구성
→ 플레이어가 각 탭에서 추론값 기록

형상 구성이 달라지면 형상 추론 탭 구성도 달라질 수 있어야 한다.

============================================================
5. 형상 추론 탭 생성
============================================================

현재 프로젝트의 부품/도면/형상 데이터 구조를 먼저 AUDIT한다.

가능하면 이미 존재하는 Geometry / Segment / Feature 데이터를
형상 추론 UI의 데이터 소스로 재사용한다.

새로운 별도 형상 데이터베이스를 중복 생성하지 않는다.

예시 개념:

Part
├─ Shape/Feature A
├─ Shape/Feature B
└─ Shape/Feature C

이면 메모의 형상 추론 영역에서도
A/B/C에 대응하는 추론 단위를 생성할 수 있어야 한다.

단, 실제 탭 이름은 현재 대상 부품의 데이터와 UI 명칭을 사용한다.
이 예시의 A/B/C를 실제 이름으로 하드코딩하지 않는다.

============================================================
6. QUEST 01 펌프 축
============================================================

QUEST 01의 펌프 축 역시 동일한 일반 규칙을 사용한다.

펌프 축이 여러 형상/구간으로 구성되어 있다면
그 형상 구성에 맞춰 추론 탭이 만들어진다.

중요:

QUEST 01이라서 코드에
"L1 탭 생성"
"L2 탭 생성"
"L3 탭 생성"

같은 퀘스트 전용 UI 생성 코드를 박는 방식은 피한다.

펌프 축의 실제 형상 데이터가 결과적으로 여러 추론 탭을 만들게 해야 한다.

============================================================
7. 측정과 형상 추론 분리
============================================================

기존 측정 시스템은 정상 상태이므로 수정하지 않는다.

다음 구조는 계속 분리한다.

TrueDimension
InstrumentReading
RecordedMeasurement
ShapeInference / PlayerInference

형상 추론 탭이 생성되더라도
TrueDimension을 자동으로 표시하거나 정답을 자동 입력하면 안 된다.

플레이어가 측정/관찰한 정보를 바탕으로
형상을 추론하고 기록하는 구조를 유지한다.

============================================================
8. 형상 추론 탭 상태
============================================================

탭을 전환해도 각 형상에 입력한 추론값이 유지되어야 한다.

예:

형상 A에 값 입력
→ 형상 B 탭 이동
→ 다시 형상 A
→ 이전 입력 유지

탭 UI를 다시 그릴 때 입력 데이터가 초기화되면 FAIL이다.

UI 상태와 실제 플레이어 기록 데이터는 가능한 한 분리한다.

============================================================
9. 닫기 버튼 위치 변경
============================================================

기존 PATCH_003에서 정의했던
'닫기 버튼 = 패널 우측 상단' 규칙을 이번 REV4에서 수정한다.

해당 UI의 닫기 버튼은:

[저장] [불러오기] [닫기]

형태로 저장/불러오기 버튼과 같은 버튼 그룹에 배치한다.

즉 닫기 버튼을 우측 상단 X 위치에 별도로 두지 않는다.

============================================================
10. 저장 / 불러오기 / 닫기 그룹
============================================================

세 버튼은 동일 Container 안에서 관리한다.

권장:

ActionButtonGroup
├─ SaveButton
├─ LoadButton
└─ CloseButton

표시:

[저장] [불러오기] [닫기]

규칙:

- 동일 Height
- 일관된 Width 규칙
- 동일 Padding
- 동일 Spacing
- 동일 Anchor 기준
- 화면비 변경 시 순서 유지
- 서로 겹치지 않음
- 클릭 영역과 시각 영역 일치

기존 저장/불러오기 기능은 수정하지 않는다.

닫기 버튼 역시 기능은 그대로 유지하고 위치만 옮긴다.

============================================================
11. 닫기 버튼 기능 보존
============================================================

닫기 버튼 위치 변경 때문에 다음을 바꾸지 않는다.

- 어떤 창을 닫는지
- 닫기 시 저장 여부
- 저장 기능
- 불러오기 기능
- 현재 데이터 상태
- Quest 상태
- 메모 데이터

기존 Close OnClick/Event를 새 위치의 버튼에 그대로 안전하게 연결한다.

기존 우측 상단 닫기 버튼 오브젝트가 더 이상 필요 없다면
중복으로 남겨두지 않는다.

화면에 닫기 버튼이 두 개 존재하면 FAIL이다.

============================================================
12. UI LAYOUT 규칙 업데이트
============================================================

PATCH_003의 공통 UI 규칙은 유지하되
닫기 버튼에 대해서는 이번 REV4가 우선한다.

즉:

OLD:
닫기 → 우측 상단

NEW:
해당 화면의 닫기 → 저장/불러오기 옆 ActionButtonGroup

[저장] [불러오기] [닫기]

다른 UI에 이미 별도의 닫기 규칙이 있고 이번 화면과 무관하다면
무조건 전 프로젝트의 모든 닫기 버튼을 이동시키지 않는다.

이번 수정 대상 화면/패널의 실제 구조를 AUDIT한 뒤
저장/불러오기와 함께 사용되는 닫기 버튼에 적용한다.

============================================================
13. QUEST WINDOW 규칙 유지
============================================================

REV3의 퀘스트 수락 구조는 그대로 유지한다.

퀘스트 발생
→ Offered
→ 기존 퀘스트 창의 수락 가능 목록에 표시
→ 플레이어가 퀘스트 선택
→ 내용 확인
→ [수락]
→ Active
→ QuestTracker/Objective 시작

이번 REV4 때문에 별도 Quest Offer 팝업을 만들지 않는다.

============================================================
14. CODEX 실행 순서
============================================================

STEP 1 — AUDIT
현재 다음 구조를 확인한다.

- 가공 방식 선택 UI
- 재료 선택 UI
- 두 선택 단계의 현재 호출 순서
- 메모 UI
- 형상 추론 탭 생성 방식
- 부품 Geometry/Segment/Feature 데이터
- 저장 버튼
- 불러오기 버튼
- 닫기 버튼 및 OnClick
- 관련 Prefab/Scene/Layout

STEP 2 — FLOW
가공 방식 선택이 완료된 후에만 재료 선택 단계로 넘어가게 한다.

STEP 3 — MATERIAL UI
재료 선택 UI를 STEP 2 흐름에 연결한다.
기존 재료 데이터/로직은 보존한다.

STEP 4 — SHAPE INFERENCE DATA
형상 추론 탭이 어떤 형상 데이터에서 생성될지 결정한다.
기존 Geometry/Feature 데이터를 우선 재사용한다.

STEP 5 — DYNAMIC TABS
대상 부품의 형상 구성에 따라 추론 탭을 생성하도록 변경한다.
QUEST 01 전용 L1/L2/L3 하드코딩은 피한다.

STEP 6 — INFERENCE STATE
탭 전환/재생성에도 플레이어의 추론 입력값이 유지되게 한다.

STEP 7 — CLOSE BUTTON
기존 닫기 버튼을 저장/불러오기와 같은 Container로 이동한다.

STEP 8 — BUTTON ORDER
[저장] [불러오기] [닫기] 순서를 적용한다.

STEP 9 — EVENT CHECK
Save / Load / Close의 기존 OnClick 연결을 확인한다.

STEP 10 — REGRESSION
Quest, 측정, Handwheel, 선반, 저장/불러오기 기능을 회귀 테스트한다.
