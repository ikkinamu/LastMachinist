LAST MACHINIST — PRESENTATION / ENVIRONMENT / SCENE COMPOSITION SPEC v1.0
작성 기준: 2026-09-13
적용 대상: Last Machinist MVP / Unity + Codex
문서 성격: 화면 연출·환경·UI 배치·씬 구성 구현 기준

0. 핵심 목적
이 문서는 '기능은 있으나 화면이 허접한 프로토타입'을 방지한다. Codex는 기능 존재만으로 완료 처리하지 않는다. 플레이어가 무엇을 보고, 어디를 바라보고, 무엇을 조작하는지 명확해야 한다.

절대 원칙:
- 스토리 화면에서는 장소와 인물이 주인공이다.
- 가공 화면에서는 기계·공작물·공구가 주인공이다.
- 측정 화면에서는 측정기와 눈금이 주인공이다.
- UI는 주인공을 가리지 않는다.
- 모든 Player-facing 텍스트는 한국어다.
- Placeholder는 개발 중 허용하지만 빈 회색 방/Cube 몇 개를 Presentation 완료로 취급하지 않는다.

1. DialoguePage
대화창은 화면 하단 약 30~35% 높이에 고정한다. 상단 65~70%는 현재 Scene과 NPC가 계속 보이는 영역으로 남긴다.

구성:
- 화자 이름
- 대사 본문
- 다음 진행 표시
- 선택지 연결 영역
- 필요 시 NPC 초상/반신 영역

개념:
┌──────────────────────────────────────────────┐
│                                              │
│            현재 Scene / 현재 NPC             │
│                                              │
│                                              │
├──────────────────────────────────────────────┤
│ 박성철                                       │
│ "에헤이~. 첫날부터 일이 생겼구먼."           │
│ "같이 가보지."                     [다음 ▶] │
└──────────────────────────────────────────────┘

금지:
- 화면 중앙 기본 팝업으로 대사 표시
- 전체 화면 불투명 대화창
- 상단 Toast 형태 대사
- 화자 이름 없이 본문만 표시
- 영어 placeholder
- 배경/인물을 완전히 가림

대화 중 Gameplay/기계 입력을 잠그고 DialogueContext를 사용한다. 종료 후 이전 Context로 복귀한다.

2. ChoicePanel
DialoguePage와 시각적으로 연결한다. 선택지는 대화창 바로 위 또는 내부 상단에 표시하며 Scene 대부분을 가리는 별도 거대 Modal로 만들지 않는다.

예:
[기본 정도는 알고 있습니다.]
[오래돼서 좀 가물가물합니다.]
[잘 모릅니다.]

3. Quest UI는 반드시 3종으로 분리
A. QuestPopup: 시작/중요 갱신/완료 순간에만 일시 표시.
B. QuestTracker: 일반 플레이 중 모서리에 2~3줄로 작게 표시.
C. QuestLogPage: 플레이어가 직접 열 때만 상세 정보 표시.

가공 중 Tracker 예:
멈춰버린 펌프
새 펌프 축을 가공하자

절대 금지:
- 가공 화면의 1/3 이상을 Quest Window가 상시 차지
- Workpiece/Tool/Vernier를 Quest UI가 가림
- 긴 Quest 설명 상시 노출

4. 공통 화면 Safe Area
Primary View Area 중앙에는 세계/NPC/공작물/측정기가 보여야 한다. Quest, Tutorial, Inventory, Debug Panel은 상시 중앙을 가리지 않는다. 큰 Modal은 플레이어가 직접 열었을 때만 허용한다.

5. LathePage
시각 우선순위:
1) Workpiece
2) Cutting Tool
3) 절삭 접촉 위치
4) X/Z Handwheel 및 조작부
5) 현재 Axis/Scale/Spindle/Tool/Mode
6) 작은 QuestTracker

개념:
┌──────────────────────────────────────────────┐
│ [작은 목표]                   [정면][평면]   │
│                               [우측][등각]   │
│                                              │
│             WORKPIECE / TOOL                 │
│                                              │
│                               [X 핸들]       │
│                               [Z 핸들]       │
├──────────────────────────────────────────────┤
│ 선택 축 X | 배율 ×10 | 주축 정지 | 황삭     │
│ [주축] [공구] [측정] [재고정] [작업 종료]   │
└──────────────────────────────────────────────┘

금지:
- 대형 Quest/Inventory/Tutorial 상시 표시
- Objective 중앙 배치
- UI가 공작물/공구 접촉부를 가림
- 고정밀 DRO 초기 상시 표시
- 마우스 휠을 Camera Zoom과 Handwheel에 동시에 사용

6. 가공 카메라
자유 카메라가 아니라 고정 Orthographic View 4개:
- 정면 Front
- 평면 Top
- 우측면 Right
- 등각투영 Isometric

Turning 기본 = 정면.
키보드 단축키와 화면 UI 버튼 모두 제공. View 전환 시 UI 위치는 유지. 마우스 휠 Zoom 금지. 향후 Milling도 같은 CameraView 시스템을 공유한다.

7. MeasurementPage
별도 Measurement System Implementation Spec v1.0을 최우선 적용한다.

시각 우선순위:
1) 확대된 버니어
2) 본척/부척 눈금
3) 측정 위치/대상
4) 직접 입력칸
5) 기록 버튼
6) Quest 정보

Quest UI가 눈금을 가리면 FAIL. 실제 치수 숫자 자동 표시는 절대 금지.

8. Workshop Scene — '빈 방 + 선반' 금지
Workshop은 김영호가 실제로 오래 사용했던 낡은 소형 가공 작업장으로 보여야 한다.

필수 Landmark:
- 범용선반: 가장 중요한 Landmark
- 작업대: 고장품 분석/측정과 연결
- 공구 보관 구역: 바이트/교환공구/공구함
- 소재 보관 구역: 탄소강 원형봉이 보관되어 있다는 시각적 정보
- 김영호 기록 공간: 노트, 책장, 종이, 작업 흔적
- 향후 설비가 들어올 빈 공간

권장 Props:
공구함, 렌치류 실루엣, 금속 봉재, 작업등, 낡은 의자, 선반/책장, 케이블, 배전함, 금속 상자, 용기, 작업 노트, 벽 표식, 금속 부품, 바닥 마모/얼룩, 오래된 조명.

모든 Props가 상호작용 가능할 필요는 없다. 목적은 '사람이 일했던 공간'이라는 정보량이다.

재질/조명:
- 바닥/벽/기계/작업대/금속 소품이 서로 구분돼야 함
- 모든 오브젝트 동일 기본 회색 Material 금지
- 낡음/금속/콘크리트/먼지/부분적 녹/사용감
- 핵심 상호작용 위치는 조명으로 읽혀야 함
- 균일한 기본 Ambient만으로 끝내지 않음

9. Farm Scene — '초록 바닥 + 펌프' 금지
즉시 농업 시설임을 알 수 있어야 한다.

필수:
- 작물 구역 또는 비닐하우스 맥락
- 물 배관
- 펌프 설비
- 수조/물탱크 또는 공급원 맥락
- 호스/배수로
- 농작업 소품
- 이서연이 여기서 일한다는 생활 흔적

권장 동선:
Scene Entry → 농업 공간 → 이서연/박성철 → Pump Landmark → 조사.
펌프를 구석에 작게 묻지 않는다.

복구 전:
- 펌프 정지
- 물 없음
- 작동음 없음
- 물 공급 중단 느낌

복구 후:
- 펌프 작동
- 물 흐름
- 물 소리
- 배관/호스/수로 변화
- 이서연 반응

10. Pump = QUEST 01 Hero Prop
단순 Cube/Cylinder 몇 개를 최종 펌프로 취급하지 않는다.

전문 지식이 없는 플레이어도 '물을 보내는 오래된 동력 기계'라고 이해할 수 있어야 한다.

필수 시각 요소:
- Motor Section
- Pump Body
- Shaft/Coupling Area
- Inlet Pipe
- Outlet Pipe
- Base/Frame
- 고정 요소
- 물 공급 방향을 이해할 수 있는 연결 구조

권장:
보호 커버, 라벨/표식, 플랜지/볼트 느낌, 배관 이음부, 녹/도장 벗겨짐, 유지보수 흔적.

멀리서도 '모터 + 펌프 + 배관' 실루엣이 읽혀야 한다.

고장 상태:
- 회전 없음
- 물 없음
- 소리 없음
- 축/커플링 영역을 조사 대상으로 읽을 수 있음
- 스토리상 박성철이 커버를 열거나 일부를 분해하는 단순 연출 가능

복구 상태:
- 회전 표현
- 약한 진동
- 작동음
- 물 흐름
- 배관/호스/수로 효과

Quest Complete 글자만 뜨고 펌프가 그대로면 FAIL.

11. NPC 배치
Workshop의 박성철은 선반/작업대 근처. Farm의 이서연은 농업 공간/펌프와 연결된 위치. Pump 조사 시 박성철은 펌프 가까이 이동해 조사 대상을 바라본다.

대화 시 현재 화자가 화면에 보이거나 카메라/시선으로 누구인지 자연스럽게 읽혀야 한다. NPC가 화면 밖인데 대사만 뜨는 상황을 피한다.

12. NPC Placeholder 최소 품질
박성철과 이서연은 최소한 실루엣/복장 맥락/초상 등으로 서로 구분 가능해야 한다. 모든 NPC를 동일 Capsule + 이름표만 바꾼 상태로 Presentation 완료 처리하지 않는다.

13. Scene Entrance / Establishing
Workshop 최초 진입: 선반, 작업대, 낡은 작업장이라는 장소성이 읽히는 구도.
Farm 최초 진입: 농업 공간, 물 관련 설비, NPC가 읽히는 구도.

짧은 Location Title 허용:
DAY 1
삼촌의 작업장

또는
농장

오래 화면을 가리지 않는다.

14. DAY 1 Presentation Flow
14.1 Fade from black → LAST MACHINIST → DAY 1 / 삼촌의 작업장 → Workshop 노출.

14.2 박성철 첫 대화: Workshop 배경 유지, 하단 1/3 DialoguePage.
"어이, 자네. 결국 이곳을 맡기로 했나."
"그런데 기본적인 가공법은 아나?"
ChoicePanel 연결.

14.3 이서연 등장: 입구 방향에서 등장하거나 등장 사실이 시각적으로 명확해야 함.
"성철 아저씨! 잠깐만 와봐요. 기계가 또 안 돌아가요!"
박성철: "에헤이~. 첫날부터 일이 생겼구먼." / "같이 가보지."
QuestPopup: 의뢰 시작 「멈춰버린 펌프」 → 잠시 후 사라짐 → 작은 Tracker만 남음.

14.4 Farm: 작은 Tracker '펌프 상태를 확인하자'. Pump 근처 [조사하기].

14.5 고장 축: DialoguePage로 진단 대사. [마모된 펌프 축]을 획득했습니다. 는 작은 Toast.

14.6 Workshop 복귀: 작업대에서 고장 축 조사 → 금속 자 → 박성철 '……뭘로 쟀나?' / '…….' / '에헤이~.' → 낡은 버니어 획득 → MeasurementPage 연결.

15. InteractionPrompt
작고 문맥적으로 표시:
[E] 조사하기
[E] 대화하기
[E] 선반 사용
[E] 작업대 확인

거대한 중앙 버튼 금지.

16. Inventory
플레이어가 직접 열 때만 큰 Page. 상시 표시 금지.
고장 축 상세 예:
마모된 펌프 축
도면 없음.
한쪽 끝에 심한 마모 흔적이 있다.
중앙이 더 굵은 3단 축 형태로 보인다.
측정/추론 전 정답 치수 금지.

17. WorkMemo
Debug Table이 아니라 작업 기록장 느낌. 대상/관찰/플레이어 측정 기록/확보 단서/추론 결과를 표시. 정보는 진행에 따라 점진 해금. 측정하지 않은 값을 자동 채우지 않는다.

18. Tutorial
큰 강의창 금지. 필요한 순간 기능 하나만 짧게. 핵심 오브젝트를 가리지 않는다.
선반 예: X/Z 축 선택, 1/2/3 배율, 마우스 휠 핸들.
버니어 첫 1회: [본척], [부척] 라벨/강조 허용. 정답 숫자 공개 금지.

19. Toast
작고 일시적. 예:
[낡은 버니어 캘리퍼스를 획득했습니다.]
[측정 기록을 저장했습니다.]
[기계구조용 탄소강 원형봉을 사용했습니다.]
여러 Toast가 무한히 쌓이지 않는다.

20. 화면 정보 밀도
밋밋함은 HUD를 늘려 해결하지 않는다. 환경 정보량을 늘린다.
좋음: 배관, 공구, 작업 흔적, 소재, 구조물, 조명, 표면 차이, 사용감.
나쁨: Quest 텍스트 8줄, HUD 숫자 15개, 거대 Tutorial, Debug 값, 불필요한 버튼.

21. UI Layer
Layer 0 World: Environment/Machine/Workpiece/NPC
Layer 1 Context HUD: InteractionPrompt/Lathe status/View buttons
Layer 2 Small Tracker: QuestTracker
Layer 3 Temporary: Toast/QuestPopup
Layer 4 Dialogue: DialoguePage/ChoicePanel
Layer 5 Modal: Inventory/QuestLog/WorkMemo/Measurement/Pause/Settings
Debug: Development Build only

22. Modal
Modal이 열리면 뒤 Gameplay 입력 잠금, 중복 입력 방지, 명확한 닫기/돌아가기, 종료 후 이전 Context 복귀. QuestTracker는 Modal 아님.

23. 한국어/Typography
한글 Glyph 지원 Font Asset 사용. 이름/대사/버튼 줄바꿈 확인. 영어 기준 좁은 버튼 금지. '가공으로 돌아가기' 같은 문자열이 버튼 밖으로 삐져나오면 FAIL.

24. Audio
Workshop: 환경음 + 선반 작동음.
Farm: 환경음 + 복구 전 정적 + 복구 후 펌프/물 소리.
Voice Acting은 MVP 필수 아님.
Pump repair는 시각 + 소리 변화가 함께 있어야 함.

25. Scene Focus Object
Workshop: Lathe > Workbench > Material Storage > Uncle's Notes
Farm: Pump > Water System > Crops > Lee Seoyeon
Lathe: Workpiece > Tool > Controls
Measurement: Vernier > Measurement Target > Input
Focus Object를 UI가 가리지 않는다.

26. Codex Audit
수정 전 반드시 현재 Scene/UI를 확인하고 보고:
- Workshop 환경 오브젝트/빈 공간/Material/Lighting
- Farm이 농장으로 읽히는지/배관/물 공급 맥락
- Pump 구성/실루엣/고장-복구 차이
- Dialogue 위치
- Quest UI 크기
- Lathe 가림 여부
- Measurement 가림 여부
그 후 수정한다.

27. PASS/FAIL — Dialogue
PASS: 하단 약 1/3, 장면 보임, 화자 이름, 읽기 쉬운 본문, 선택지, 한국어.
FAIL: 중앙 기본 팝업, 전체 화면 덮기, 배경 차단, 영어 placeholder, 화자 구분 없음.

28. PASS/FAIL — Quest
PASS: 시작/완료는 Popup, 진행은 작은 Tracker, 상세는 QuestLog.
FAIL: 가공 화면 1/3 이상 Quest가 상시 점유, Workpiece 가림, 긴 설명 상시 노출.

29. PASS/FAIL — Workshop
PASS: 스크린샷만 보고 '낡은 기계 작업장'이라고 인식. 선반/작업대/공구/소재/기록 공간 구분.
FAIL: 빈 벽+빈 바닥+선반 하나, 기본 Primitive 그대로, Material 모두 동일.

30. PASS/FAIL — Farm
PASS: 물 공급 문제가 생긴 농업 공간이라는 맥락을 시각적으로 이해.
FAIL: 펌프만 덩그러니, 작물/배관/공급 구조 없음.

31. PASS/FAIL — Pump

37. 최종 원칙
Last Machinist의 화면은 '기능이 있다는 것을 증명하는 개발자 화면'이 아니라 '플레이어가 세계와 기계를 보고 이해하고 조작하는 게임 화면'이어야 한다.

가공 화면에서는 기계와 공작물이 주인공이다.
측정 화면에서는 측정기와 눈금이 주인공이다.
스토리 화면에서는 장소와 인물이 주인공이다.
UI는 그 주인공들을 가리지 않는다.
